# 设计参考与设计决策

本文说明思政教学案例智能平台前端的设计来源：参考了哪些产品、对它们的组件做了什么分析、哪些逻辑组件被复用，以及最终的视觉与交互决策是如何得出的。

分析基于两部分材料：一是 2026-07-16 归档的参考清单（旧版本文，所有网址当时经验证可访问），二是对各产品公开界面与交互的研究。本文不堆砌链接，只记录真正影响了设计的结论。

---

## 一、设计约束（来自需求方的硬要求）

在挑选参考之前，先明确约束，参考是为约束服务的：

1. 界面不允许出现元表述（"这个面板是用来给老师××的"、功能原理说明、原型字样），方法解释全部放在对话里；
2. 功能必须完整（PRD 六大功能 + 领导批注），视觉可以让步，但交互不能残疾；
3. 编辑器要"Word 式"——教师面对的是一份文档，不是一堆卡片；
4. 不允许"一个需求一个按钮"的特化设计，能合并的维度必须合并（用途并入模板即由此而来）；
5. 党政红基调，但要"庄重而不土"。

## 二、各模块的参考与组件分析

### 2.1 案例编辑器（工作台）

**参考：ChatGPT Canvas、Lex、Typora、飞书文档、WPS AI、Google Docs 建议模式、Cursor**

组件分析：

- **ChatGPT Canvas** 确立了"文档占主视觉、AI 收在侧栏"的空间分配。分析其交互后提炼出的可复用逻辑是：**AI 的产出永远是"提案"，正文只由人确认后写入**——这直接对应 PRD"未经教师确认不替换正文"。我们据此设计了结果卡片上的采用按钮组（替换当前节 / 追加到当前节 / 存为新节 / 写入教学材料），而不是让 AI 直接改文档。
- **Lex 与 Typora** 证明了一件事：面向写作的界面，正文应该用衬线、大行距、两端对齐，页面上只留文字本身。编辑器因此做成一页完整的自由文档（`.doc-editor`）——白纸、阴影、衬线正文（15.5px/2.0 行距），标题只是带格式的文字（工具条提供 加粗/标题/正文 三种格式），任何文字都可自由增删，模板章节只是初始脚手架；不做分节卡片、不做块级拖拽。
- **Google Docs 建议模式与 Cursor 的 diff 确认** 提供了批注的生命周期模型：修订在正文原位显示增删高亮与理由，逐条采纳或拒绝，低风险建议可以批量采纳。批注面板复用待处理、已采纳、已拒绝、已解决、已失效五种状态，并按 Grammarly 的分级思路把错别字、格式类标为低风险。
- **WPS AI / 飞书 AI** 是中文政企场景里右侧 AI 栏的成熟形态：输入框贴底、快捷指令以 chips 形式横排在输入框上方。Copilot 面板的布局与此一致。

未采用的部分：Notion 的块编辑。教学文档保持连续纸张结构，不提供块级拖拽。

### 2.2 公共搜索门户

**参考：秘塔 AI 搜索、Perplexity（Mobbin 截图）、夸克、Harvard Business Publishing、国家高等教育智慧教育平台、中国大学 MOOC**

组件分析：

- **秘塔**的信息架构是"大圆角搜索框 → AI 概述 → 分组结果 → 每条带来源与引用"。公共检索沿用胶囊搜索框、条件式 AI 回答和案例/知识/素材结果；AI 只使用当前用户可见的前 15 条结果，引用以编号链接跳转。
- 秘塔与 Perplexity 的**引用角标**对应我们的"命中原因"行：每条结果显示命中的字段与上下文片段并高亮关键词，解释"为什么这条结果出现"——PRD 明确要求"解释命中原因"。
- **HBP（hbsp.harvard.edu，本次实地查看）**：结果类型页签与分面选项显示数量。公共检索沿用页签和分面计数，筛选集中在页签右侧的下拉菜单与条件标签，结果每页 20 条并使用游标翻页。
- **智慧教育平台与大学 MOOC（本次实地查看）**：中文教育平台惯用"全部 + 筛选条件行"的 chips 样式与"为您找到 N 门"的结果计数。我们的标签分面与页签计数沿用了这一中文习惯。
- **高校思政网（本次实地查看）**：频道制顶层分类（政策文件/典型经验/资源服务…），证明思政内容适合"类型频道 + 标签"而非文件夹树。
- 排序采用 Meilisearch 词面匹配，发布时间、标题、类型和 ID 提供稳定次序。

### 2.3 知识图谱

**参考：Obsidian Graph view、Neo4j Bloom**

组件分析：

- Obsidian 图谱的可用性关键不在布局算法，而在**悬停聚焦与图例**。我们复用了：节点按类型着色 + 右上角图例、悬停显示完整标题的气泡（图上标签统一截断，完整名靠悬停）。
- Bloom 的"点击节点 → 查看实体属性"对应我们的"点击节点 → 跳转对应详情页"（案例/知识/素材页）。图谱在信息架构里是导航入口，不是分析工具，因此没有照搬 Bloom 的右侧属性面板。
- 力导向布局本身（节点斥力 + 引用边弹簧力 + 向心引力）是教科书实现，Canvas 手写、无第三方依赖，满足"可拖动、可缩放、可平移、双击复位"。

### 2.4 审核后台

**参考：Ant Design Pro、飞书审批**

组件分析：

- Ant Design Pro 的中后台范式——**页签切分领域、表格承载实体、状态用色签**——是整个管理后台的骨架（案例审核/发布管理/素材管理/类型与模板/知识库/账号权限）。
- 飞书审批的动作组设计（通过 / 退回 / 要求补充，意见与动作绑定）复用于审核详情页：退回与要求补充必须填意见才能提交，通过可不填；线下意见来源（思政教研组/宣传部）作为独立字段录入，对应 PRD"管理员可录入线下意见"。
- "先冻结、再审"的流转（开始审核 → 冻结待审版本）来自 PRD 与领导批注 22，不是界面参考。

### 2.5 视觉基调

**参考：学习强国、高校思政网、北京大学官网、国家高等教育智慧教育平台、Craft**

组件分析：

- 党政红的高级用法，北大官网是最干净的样本：**大面积留白 + 一个正红 + 衬线标题字**，红色只出现在关键动作与关键信息上。学习强国证明红+暖金可以并存，但金色只能作点缀（焦点环、高亮标记），不能作主色。
- higher.smartedu.cn 证明了红色主题与现代 SaaS 组件（圆角卡片、胶囊筛选）可以兼容，不会显得像上世纪的政务网站。
- Craft 的排版给了正文页的细节标准：段落间距大于行内间距、标题层级靠字重而非颜色区分、两端对齐。

## 三、复用的逻辑组件清单

从上述分析中沉淀下来、与本平台业务无关也能复用的逻辑组件：

1. **提案-确认卡片**：AI 产出先展示、带动作按钮、确认后才写入目标位置。用于 Copilot 全部内容型指令。
2. **任务时间线**：长任务拆成阶段清单，进行中/完成/失败三态 + 重试入口。用于 Copilot 任务与任务页签（对应批注 24、26、27）。
3. **批注状态机**：五状态 × 三来源的二维筛选 + 低风险批量采纳 + 失效重挂载。
4. **引用角标 + 内容副本**：引用指向采集时保存的副本而非实时网页，素材详情页展示副本与采集时间（对应批注 3）。
5. **可信度标签 + 白名单**：来源域名命中白名单即为权威来源，反之为待核实；采集时自动判定。
6. **队列-冻结-发布状态机**：草稿 → 待审（可撤回）→ 审核中（冻结）→ 已发布（快照固定），公开页只读快照。
7. **模板即用途**：模板自带用途属性（日常授课/集体备课/案例申报），消灭一个独立的筛选维度。
8. **会话内检索缓存**：同一案例的 Copilot 会话中，检索结果按查询缓存，避免重复检索（对应批注 8）。

## 四、最终视觉决策

在约束与参考之上，实际落地的设计系统：

- **色彩**：主色取校徽红 `#BA1C22`（从上海大学校徽取样），辅以西式暖纸底 `#F6F4EF`；金色 `#B08D57` 只用于焦点环与关键词高亮；语义色（绿/琥珀/蓝/红）只出现在状态标签上。红色因此有了双重含义：既是党政红，也是上大红。
- **字体**：UI 骨架（导航、按钮、表格、标签）用无衬线黑体；文档与标题用衬线宋体（思源宋体/宋体回退）。原则是"机器界面用黑体，人的文字用宋体"——案例正文、教材正文、引用副本全部是衬线，接近印刷品。
- **质感**：页面是纸。工作台文档、引用副本、详情页正文都做成白纸 + 柔和投影，背景是暖灰，让"纸"浮起来。卡片圆角 10px、按钮圆角 8px、搜索框全胶囊，阴影统一用暖棕色调而非纯黑。
- **动效**：只做状态反馈型动效——悬停浮现操作、弹窗淡入上浮、卡片悬停微抬升、任务圆点呼吸。不做营销型动效（滚动视差、入场动画），与"界面无元表述"的约束一致。
- **品牌**：顶栏左侧为上海大学校徽横式 logo + 衬线平台名，校徽同时作为 favicon；管理后台、审核页等 G 端页面保持表格化、低密度装饰。

反模式清单（明确不做的）：营销式标语与功能解说文案；一个需求一个按钮的特化控件；块级拖拽编辑；默认触发的 AI 概述；图谱上的原理解说标注。
