# Agent 对话中的 Skill、工具与上下文控制
## 已验证的产品模式
| 问题 | 一手事实 | 可复用结论 |
| --- | --- | --- |
| Composer 常驻与折叠 | VS Code Chat View 将会话置顶、历史置中、输入区置底；输入区承载 target、agent、model 与 permission。`#` 和 Add Context 打开统一选择器，工具细项经 Configure Tools 选择，而不常驻铺开。[Chat View](https://code.visualstudio.com/docs/agents/run/chat-view) [Context](https://code.visualstudio.com/docs/chat/copilot-chat-context) [Tools](https://code.visualstudio.com/docs/agents/run/tools) LibreChat 在运行中保留 composer 已输入文字，并在同一发送位提供 steer、queue、interrupt-and-steer、interrupt-and-send 或 stop。[During-run composer](https://github.com/danny-avila/LibreChat/blob/64258372699a6b2fa7401681ccb48b0d0bdc7a63/client/src/components/Chat/Input/DuringRunSendButton.tsx) | 常驻输入、已附上下文摘要、当前工作流/权限；把工具、MCP 与连接器明细收进有搜索的能力面板。 |
| 多上下文附件 | Copilot 可把文件、目录、符号、工具、终端输出、SCM 改动、图片、网页元素、截图和控制台日志加入同一轮上下文；显式项可由 `#`、Add Context 或拖放加入。[Context](https://code.visualstudio.com/docs/chat/copilot-chat-context) | 上下文是有类型、稳定 ID、可逐项移除的附件集合，不应只作为截断的文本 token；“已选 N 项”应始终可见，细节按需展开。 |
| Skill 与 Tool | VS Code 将 Skill 定义为可按需加载的 instructions/scripts/resources，`/` 可显式调用且 frontmatter 可控制用户可见性；Tool 是内置、MCP 或扩展提供的可调用能力。[Agent Skills](https://code.visualstudio.com/docs/agent-customization/agent-skills) [Tool concepts](https://code.visualstudio.com/docs/copilot/concepts/tools) Open WebUI 也把 Model、Knowledge、Prompt、Skill、Tool 分为独立 Workspace 资源。[Workspace](https://docs.openwebui.com/features/workspace/) LobeHub 当前把 Skill 定义成可暴露一个或多个 tools 的能力包，术语不同于前两者。[LobeHub Skill management](https://github.com/lobehub/lobehub/blob/e1069fad6f50284e0eedff3065421a3cddfbdf42/docs/usage/community/skill-management.mdx) | Skill/工作流选择和 Tool/MCP 授权应分开建模与分 tab 呈现；Skill 说明“如何工作”，Tool 表示“可执行什么”。不要从第三方产品名称反推领域含义。 |
| MCP/Connector 的边界 | VS Code 将 MCP 的 tools、resources、prompts、apps 区分处理：tools 可逐项启用，resources 作为只读上下文，prompts 从 `/server.prompt` 调用，禁用 server 会排除全部表面。[MCP servers](https://code.visualstudio.com/docs/agent-customization/mcp-servers) | 不把 Connector 简化成一个开关：至少区分其可调用工具、可附上下文资源、提示模板和连接状态。用户只能从已批准的目录选择，不能在 composer 输入任意服务端地址或密钥。 |
| 当前启用项 | Copilot 的 Configure Tools 支持本次搜索、选择和取消选择；Open WebUI 的 Integrations > Tools 在会话中切换工具，模型默认工具仍会按用户 read access 过滤。[Use tools](https://code.visualstudio.com/docs/agents/run/tools) [Open WebUI tools](https://docs.openwebui.com/features/extensibility/plugin/tools/) LibreChat 的 MCP 菜单先按使用权限过滤，再显示 selected、连接状态和初始化状态；其输入组件将 MCP、Tool、Skill 与已选 Skill chips 分开。[MCP select](https://github.com/danny-avila/LibreChat/blob/64258372699a6b2fa7401681ccb48b0d0bdc7a63/client/src/components/Chat/Input/MCPSelect.tsx) | 发送前应以紧凑摘要明确显示：工作流/版本、附件数、已启用工具数、连接器状态；“可用”与“本轮实际调用”不得混为一谈。 |
| Permissions 与 approval | Copilot 的 session permission picker 是会话总开关；需确认的调用展示工具名和参数，可批准单次、session、workspace 或未来调用。URL 请求与返回内容分两段确认，避免把外部内容直接注入上下文。[Approvals](https://code.visualstudio.com/docs/agents/run/approvals) Open WebUI 将 Tool/Function 视为可执行任意 Python/服务器 shell 的高风险代码，默认应限可信管理员管理。[Hardening](https://docs.openwebui.com/getting-started/advanced-topics/hardening/) LobeHub 在等待人工干预时持久化 approved/rejected 与 pending tool-call 状态，全部解决后才回到运行态；其 approval card 按会话分组并以 tool-call ID 切换待审项。[Handler](https://github.com/lobehub/lobehub/blob/e1069fad6f50284e0eedff3065421a3cddfbdf42/apps/server/src/services/agentRuntime/HumanInterventionHandler.ts) [Approval card](https://github.com/lobehub/lobehub/blob/e1069fad6f50284e0eedff3065421a3cddfbdf42/src/features/GlobalApprovalNotification/ApprovalCard.tsx) | “已启用”不是“已批准”。审批卡应绑定具体 call ID、参数摘要、风险/副作用和批准作用域；服务端仍须按当前身份、资源和参数重验。 |
| 实际调用、来源与产物 | Copilot 默认折叠 tool trace，可按摘要展开并配置分组；LibreChat 前端将 ToolCall、ToolCallGroup、ToolApproval、ActivityPhaseGroup、SkillPills 和 Artifacts 拆成独立组件，其活动折叠不会卸载未决审批状态。[VS Code tools](https://code.visualstudio.com/docs/agents/run/tools) [LibreChat trace](https://github.com/danny-avila/LibreChat/blob/64258372699a6b2fa7401681ccb48b0d0bdc7a63/client/src/components/Chat/Messages/Content/ActivityPhaseGroup.tsx) [LibreChat chat components](https://github.com/danny-avila/LibreChat/tree/64258372699a6b2fa7401681ccb48b0d0bdc7a63/client/src/components/Chat) Open WebUI 将 citation 和 tool display 独立渲染。[Open WebUI chat components](https://github.com/open-webui/open-webui/tree/d3e8bf3405e848cfba377814d0aa7ba7290e414d/src/lib/components/chat) | 完成态调用应收成一行“名称、结果、耗时、来源数”，进行中、错误和待批准默认展开；引用/文件/待确认修订是独立 part 或 artifact，不能伪装成助手文本。 |
| 窄侧栏 | Copilot 将 session、历史和 composer 划为三个稳定区域；当侧栏不足以承载任务时可转 editor tab 或独立窗口。[Chat View](https://code.visualstudio.com/docs/agents/run/chat-view) LobeHub 的右栏可拖宽，并定义 300--600px 的边界。[RightPanel](https://github.com/lobehub/lobehub/blob/e1069fad6f50284e0eedff3065421a3cddfbdf42/src/features/RightPanel/index.tsx) | 侧栏只保留一个主要滚动面：历史滚动，composer 固定。选择器和细节面板要有明确高度、焦点和关闭行为；复杂配置可升级为更宽视图。 |
## 运行时与前后端边界
OpenAI ChatKit session 由 `user`、workflow 和配置创建，配置包括 history 与 file upload；短期 client secret 仅认证该 session。[ChatKit session](https://developers.openai.com/api/reference/typescript/resources/beta/subresources/chatkit/subresources/sessions/methods/create) Responses API 将输出、工具调用和取消作为类型化 API 项，而非一段最终文本。[Responses create](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)
Vercel AI SDK 的 `UIMessage.parts` 包含 text、reasoning、tool、source、file、data 与 step；流协议还区分工具输入、approval request/response、output/error/denied、source、finish 与 abort。[UI message source](https://github.com/vercel/ai/blob/main/packages/ai/src/ui/ui-messages.ts) [Stream chunks source](https://github.com/vercel/ai/blob/main/packages/ai/src/ui-message-stream/ui-message-chunks.ts)
据此推断，浏览器应只投影服务端的 `thread`、`message/part`、`run`、有序 `event`、能力选择快照、`tool_call`、`approval`、`source` 与 `artifact`。前端提交意图和已选受权条目；后端重建模型输入、授权并执行工具、持久化实际事件。此为可复用状态边界，不是产品架构决定。
## Vue 3 与前端源码取向
直接可复用的 Vue 3 层是 [`@ai-sdk/vue` 的 `useChat`](https://github.com/vercel/ai/blob/main/packages/vue/src/use-chat.ts)：它以 `VueChat`/响应式 ref 提供 messages、status、error、stop、resume 与 transport；不是带 composer、附件、审批或 trace 的成品 UI。[官方 API](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat) [Vue 测试](https://github.com/vercel/ai/blob/main/packages/vue/src/chat.vue.ui.test.tsx)
未发现可直接复制的成熟 Vue 3 Agent 工作台组件。VS Code 是 workbench TypeScript，可借鉴 [`chatInputPart.ts`](https://github.com/microsoft/vscode/blob/004a1fbb1658e61048b29d76e2ce380adfa18680/src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts)、[`chatAttachmentModel.ts`](https://github.com/microsoft/vscode/blob/004a1fbb1658e61048b29d76e2ce380adfa18680/src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentModel.ts) 与 [`chatSelectedTools.ts`](https://github.com/microsoft/vscode/blob/004a1fbb1658e61048b29d76e2ce380adfa18680/src/vs/workbench/contrib/chat/browser/widget/input/chatSelectedTools.ts) 的状态拆分。Open WebUI 是 Svelte，可借鉴 [`MessageInput`](https://github.com/open-webui/open-webui/blob/d3e8bf3405e848cfba377814d0aa7ba7290e414d/src/lib/components/chat/MessageInput.svelte)、[`IntegrationsMenu`](https://github.com/open-webui/open-webui/blob/d3e8bf3405e848cfba377814d0aa7ba7290e414d/src/lib/components/chat/MessageInput/IntegrationsMenu.svelte)、[`ToolServersModal`](https://github.com/open-webui/open-webui/blob/d3e8bf3405e848cfba377814d0aa7ba7290e414d/src/lib/components/chat/ToolServersModal.svelte) 与 citation/tool display 的职责边界；LibreChat 是 React，可借鉴上述输入、审批、trace 与 artifact 组件边界，而非跨框架直接移植。
## 可复用推断
- composer 保持“输入 + 附件摘要 + 能力摘要 + 发送/停止”；Skill、工具/MCP、连接器配置和长清单均折叠。
- Skill 版本固定到运行快照；工具选择固定到本轮或会话的授权范围；实际调用、审批和来源只从运行事件渲染。
- 在窄栏中，已完成 trace 默认折叠，用户离开底部阅读历史时停止自动跟随并显示新事件计数；不要同时隐藏多个滚动区域的滚动线索。
- 前端测试覆盖 composer 的附件去重/移除、能力摘要、权限与 approval 显示、part 渲染和“未贴底不自动滚动”；端到端测试覆盖服务端授权、真实 tool-call、审批、刷新重放、停止与来源/产物恢复。AI SDK 对 Vue hook 与底层 Chat 保留独立测试，可作为分层测试参考。[Vue tests](https://github.com/vercel/ai/blob/main/packages/vue/src/chat.vue.ui.test.tsx) [Chat tests](https://github.com/vercel/ai/blob/main/packages/ai/src/ui/chat.test.ts)
