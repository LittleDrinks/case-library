## 结论先行

- **“caseID + enum”不是当前资料的唯一身份。** 若 enum 指显示序号 `〔1〕`，它由正文引用顺序和其余条目的加入顺序动态生成；若指来源类型枚举，单个案例中同类资料可以有多条。正文持久化的是 `sourceType + sourceId`，保存时在 `caseId` 范围校验这对引用。[正文标记约束](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/document_schema.py#L112-L122)、[引用归属校验](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/citations.py#L9-L40)、[编号生成](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/sources.py#L21-L35)。
- **当前案例资料区有三类：附件、全局素材挂载、其他案例的固定版本来源。** “来源”标签是三类合并后的带编号列表，不仅是其他案例。知识源另有全局检索与 Agent 读取能力，但不在当前正文 citation 类型或案例资料区集合里。[条目合并](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/sources.py#L38-L57)、[资料区 UI](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/frontend/src/components/AttachmentPanel.vue#L133-L156)、[知识读取](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/agent/source_reader.py#L147-L155)。
- **全局 materials 已有实际导入、审批、检索、详情、下载和挂载链路，不仅是种子数据。** knowledge 也有实际公开读取与检索链路，但当前内容入口是内置教材启动种子，没有通用教材上传/审批管理 API。[素材路由](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/materials/routes.py#L29-L124)、[知识路由](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/knowledge/routes.py#L8-L13)、[启动种子边界](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/core/bootstrap.py#L14-L23)。

## 唯一身份与显示编号

| 实体 | 当前真实身份与唯一约束 | 正文 `sourceId` 是什么 |
| --- | --- | --- |
| 案例附件 `attachments` | 随机 `att-<hex>`，`id` 全局唯一，记录另含 `caseId`；字节有独立随机 `blobId`。 | 附件 `id`，来源类型为 `attachment`。 |
| 全局素材 `materials` | 素材 `id` 全局唯一；导入审批使用候选 `id`，候选另按内容 SHA-256 去重。 | 全局素材 `id`，来源类型为 `material`。 |
| 案例挂载素材 `case_materials` | 唯一约束是 `(caseId, materialId)`；同一个全局素材可以挂入多个案例。挂载记录视图仍使用素材 `id`。 | `materialId`；校验的是当前案例的挂载关系。 |
| 案例来源 `case_sources` | 随机 `src-<hex>`，`id` 全局唯一；另有 `(caseId, sourceCaseId, versionId)` 唯一约束。 | 挂载关系的 `src-…`，来源类型为 `case`；不是原案例的 `caseId`。 |
| 案例版本 `case_versions` | 版本 `id` 全局唯一，另有 `(caseId, number)` 唯一约束。 | 这是案例版本序号，和资料区来源编号是不同的数字。 |

资料区编号计算：按正文首次出现的 `(sourceType, sourceId)` 排引用条目，未引用条目按 `createdAt`、ID 排在后面，最终 `enumerate(..., start=1)` 写入响应的 `number`。移动/增加/删除正文引用可能改变显示编号，来源 ID 本身不因此改变。编辑器只保存来源 ID 标记，再从资料列表获得 `number`，用 decoration 展示 `〔number〕`，数字不是持久化标记的一部分。[首次引用排序](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/citations.py#L16-L19)、[编号及余项排序](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/sources.py#L21-L35)、[排序键](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/backend/app/modules/cases/sources.py#L60-L79)、[插入标记](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/frontend/src/components/CanvasEditor.vue#L714-L725)、[显示编号](https://github.com/LittleDrinks/case-library/blob/7afc5bb9e182b1c61827d6024670002a42937fc6/frontend/src/lib/citation.js#L166-L208)。

## 全局 materials：已实现链路与空缺

## 通用 PDF、教材、政策能走哪个已有路径

| 具体教师动作 | 当前可用路径 | 已实现的结果与限制 |
| --- | --- | --- |
| 只把一个 PDF/教材/政策文件放在当前案例资料区 | 草稿资料区“附件 → 上传” | 创建属于该案例的附件，进入统一来源编号并可插入正文引用；原始 PDF 能存储和下载，当前 PDF 正文不能被文字抽取器读取。 |
| 让文件成为平台可检索、多个案例可复用的素材 | 管理员“素材入库 → 文件导入 → 批准”，教师“素材掌控台 → 加入当前案例” | 创建独立全局 material，再建每个案例的挂载关系。格式检查明确包括 PDF；审批 API 可填写来源、摘要、类型等，当前审批 UI 主要编辑标题。 |
| 把教材变成按章节检索/阅读的结构化知识 | 现有内置教材 seed 链路 | 该指定教材可读；任意新教材的导入/切章/更新管理不是已实现入口。knowledge 节可供 Agent 读取，但不能直接当当前案例 citation 类型挂载。 |
| 引用另一篇已发布案例 | 案例页“加入我的案例”所用 case-source API | 建立固定来源案例版本的关系，不复制为本案例附件。 |

## 规格与未验证项

用户提出“素材只跟着案例走、保留现有体验”是本轮需要澄清的产品方向；本笔记没有将它写成已确认规格，也不据此删除现有全局 materials 或 knowledge 模型。现有入口已经同时支持“案例自己的附件”和“全局素材挂入案例”。显示仍可保留统一 `〔编号〕` 体验，是否统一底层身份/取消全局复用是另外的领域决定。

没有用静态代码推断生产是否已有真实素材/教材、前端当前部署版本、Agent 的实际提供者运行或 Meilisearch 索引健康。已实现的读取链路、只能靠 seed 的写入链路、缺失 API 和本轮产品意向已分别标明；本次不新增实施票或替用户决定归属规则。
