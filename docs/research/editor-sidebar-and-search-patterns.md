# 教师编辑台：批注侧栏与海量资料检索

## 结论

- 正文始终占据主工作区；侧栏只呈现与当前选区、光标段落或当前任务有关的内容。
- 批注需要两个互斥视图：正文旁的上下文视图只显示当前可见区域内未解决的批注，全量视图集中处理所有批注。默认不把全部批注卡片沿正文铺开。
- 海量内容不能用“筛选条件 + 结果列表”直接暴露给教师。教师主动委托 Agent 检索，服务端完成大范围召回、重排、去重和片段提取，独立结果页首屏只交付 3–5 条候选。
- 站内检索交付可引用的案例版本；站外检索交付可加入当前案例的附件。AI 只负责压缩候选和解释关联，不能把 AI 摘要当作事实依据。

## 批注：上下文处理与全量治理分离

Microsoft Word 将批注明确分成 Contextual 和 List 两种视图：上下文视图把批注放在对应插入点附近，只显示活动批注并隐藏已解决批注；列表视图集中显示活动与已解决批注，选择一条后同步高亮正文并滚动到锚点。[Microsoft Word：Modern comments](https://support.microsoft.com/en-us/word/using-modern-comments-in-word)

Google Docs 支持按关键词或用户名搜索批注、筛选批注、回复与解决讨论；已解决批注仍可在原文档中访问。[Google Docs：Comments and action items](https://support.google.com/docs/answer/65129?hl=en&co=GENIE.Platform%3DDesktop)

Notion 将批注绑定到选中文本、光标位置或单个内容块；页面批注面板可按人员和开放/已解决状态筛选，点击批注返回原位置，未读状态通过图标红点表达。[Notion：Comments, mentions and reactions](https://www.notion.com/help/comments-mentions-and-reminders)

### 教师编辑台交互

- 正文只显示细窄锚点标记；当前锚点展开一条线程，其余线程折叠为头像、数量和状态，不形成卡片瀑布。
- 点击正文锚点时，侧栏聚焦对应线程；点击侧栏线程时，正文滚动并高亮对应文字。两处共用同一选中状态。
- 默认视图只含当前可见区域的未解决批注。顶部批注图标承载未读数量，打开后才进入全量视图。
- 全量视图提供人员、状态与关键词筛选；已解决批注进入归档，不占据日常审阅空间，但允许重新打开。
- 新批注必须绑定精确文本范围或光标位置；块级批注只用于整段结构意见。
- 同一锚点只展开一个线程；回复、解决、重新打开使用固定图标动作，状态变化立即反映到正文锚点。

## 检索：从结果浏览改为候选收敛

Elicit 允许直接输入自然语言研究问题，以语义检索覆盖超过 1.38 亿篇论文，不要求用户枚举全部关键词；首轮只加载最相关的 10 条，再按 10 条增量展开。结果先给主题摘要和论文表格，再通过自定义列、筛选与对话继续分析。[Elicit：Find Papers](https://support.elicit.com/en/articles/14757543-getting-started-with-elicit-which-workflow-or-tool-should-i-use)

Elicit 公布的检索流程不是一次向量排序，而是语义嵌入召回候选、相关性模型重排、截取高分集合、按纳入/排除条件筛选四阶段。[Elicit：Search methodology](https://support.elicit.com/en/articles/14757952-citing-elicit-search-methodology-and-using-elicit-s-content-in-your-own-work)

Notion Enterprise Search 默认跨工作区、连接应用与网页检索，也允许把范围收窄到单一来源、页面或团队空间；AI 回答始终附来源，用户可以回到原始内容。[Notion：Enterprise Search](https://www.notion.com/help/enterprise-search)

Zotero 的全文索引在后台构建，快速搜索可检索附件正文，高级搜索可保存为持续自动更新的智能集合。标签选择器只展示当前集合与当前结果中实际存在的标签，无匹配标签置灰，筛选范围随结果联动收缩。[Zotero：Searching](https://www.zotero.org/support/searching) [Zotero：Collections and Tags](https://www.zotero.org/support/collections_and_tags)

### 教师编辑台交互

- 教师在 Agent 面板主动提出需求；选中文字或当前段落只作为可选上下文，不触发后台判断或自动检索。
- Agent 完成查询改写后返回结果链接。链接在新页面打开，正文编辑状态保持不变。
- 服务端按“关键词与语义召回 → 权威性/相关性/时效性重排 → 同事件与转载去重 → 证据片段提取”处理全库，浏览器不接收全量结果。
- 结果页首轮固定显示 3–5 条候选。站内结果展示案例版本、作者、发布时间和命中片段，动作是“引用案例”；站外结果展示来源、日期和原文片段，动作是“加入附件”。
- AI 概括展示为候选组级别的可选视图。打开候选时展示原文上下文并高亮命中句；事实依据始终绑定附件原文，案例引用始终绑定不可变已发布版本。
- 搜索范围显式区分“站内案例”和“互联网”，不能把两类结果静默混入一组。
- 筛选项来自当前候选集的动态分面；无命中项置灰。站内保留课程、类型、学段和发布时间；站外保留来源、时间与内容类型。
- “更多结果”每次增量加载少量候选；教师排除、引用案例或加入附件后，系统据此重排剩余候选，不要求浏览数百条结果。

## 页面状态

| 教师动作 | 编辑台 | 检索结果页 |
| --- | --- | --- |
| 选中文字 | 仅形成可发送给 Agent 的上下文 | 不打开 |
| 委托 Agent 检索 | 保持正文与光标位置，显示任务进度 | 任务完成后可由链接打开 |
| 打开结果链接 | 保持编辑状态 | 显示首批 3–5 条引用候选 |
| 引用案例 | 保持编辑状态 | 记录被引用案例版本，允许继续筛选 |
| 加入附件 | 保持编辑状态 | 写入当前案例，允许继续筛选 |
| 返回编辑台 | 恢复原光标位置 | 保留任务结果 |
| 点击批注锚点 | 侧栏聚焦单条线程 | 不变 |
| 打开全量批注 | 侧栏进入人员、状态、关键词筛选列表 | 不变 |

## 原型验收标准

- 一屏出现 30 条未解决批注时，正文宽度不变化，侧栏最多展开一个线程，教师可在上下文视图与全量视图间切换。
- 案例库达到一万条时，教师主动提交的 Agent 任务通过真实 API 检索；首屏候选不超过 5 条，每条都能查看命中片段并引用具体版本。
- 互联网检索通过真实 API 返回来源，加入后形成当前案例附件与原文副本。
- 切换检索范围、排除、引用案例、加入附件与加载更多均由服务端真实数据驱动；页面刷新后业务数据仍存在。
- 任意 AI 摘要都不能成为事实依据；正文中的每个事实依据能返回具体附件与原文片段，每个案例引用能返回具体案例版本。
