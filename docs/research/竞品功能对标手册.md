来源：两份竞品调研报告（非一手资料，原文已删除；老师开会定的方向才是一手资料）+ 2026-08 补充搜索（RagFlow、蜜度校对通、Gemini Notebook、Coze 定时任务）。

使用方式：本手册按**功能**重新划分调研内容。每个功能下列出"每个竞品具体是怎么做的"（机制颗粒度），末尾给出对本 demo 的启示。

## F1 素材采集与自动盯源

**要解决的问题**：权威信源持续产出新内容，靠教师手工找素材既慢又漏；但自动采集不能污染素材库。

### 竞品具体做法

- **Coze 扣子空间（定时任务）**：用户用自然语言描述任务时间和内容（如"每天早上 9 点从指定新闻网站搜集特定主题信息"），Agent 自动创建定时任务并周期执行。工作流节点可零代码串联：HTTP 请求抓取网页 → html 转 markdown 净化 → LLM 解析提取核心信息 → 文本重组生成日报 → 定时推送/同步到飞书多维表格。已有大量"每日新闻采集日报"模板可直接复制。
- **Feedly AI**：按主题自动筛选并持续更新信息流，是"订阅制信息流"的成熟产品形态。
- **Visualping**：监测指定网页变化并生成变化摘要，适合没有 RSS/API 的页面。
- **n8n / Zapier**：用 RSS、定时器、向量库、消息、邮件节点自建采集与分发管道。
- **腾讯 WorkBuddy**：以自然语言"派任务"，支持 Skill、专家、专家组三级抽象与多 Agent 并行；官方将自动生成教案、测验、评分量规列为教育场景。团队权限与资产共享机制适合组织级采集任务。
- **新华思政（人工对照组）**：高校推荐或教师自行申报 → 学校书面同意并盖章 → 平台审核后上线。申报规范要求保证内容无政治性、科学性错误，未知出处素材须标注"仅供教学使用"——这是一套人工时代的入库流水线，可直接数字化。

### 版权红线

新华社稿件受版权保护，新华思政明确声明平台内容的信息网络传播专有使用权。未获授权时默认只存**标题 + 摘要 + 原文链接 + 出版元数据 + 证据片段 + 内容指纹**，获得授权后再存全文。

### 对本 demo 的启示

- 自动盯源管道：定时检查白名单栏目 → 识别新增/变更 → 去重 → 分类 → 提取事实关键词 → 关联知识点 → 生成**候选素材卡** → 风险与版权检查 → 编辑审核 → 入正式库。
- 自动任务产出一律是"候选素材"，政策、理论、重大时事必须由内容编辑确认后才进教师可用库（先审后发）。
- 存储治理：同一事件的多方报道聚类为一条"事件卡"，最高权威信源版本为正文、其余作为多方验证附件，而非全量无脑存储。

## F2 素材治理：信源分级、白名单、置信度

**要解决的问题**：通用大模型的信源是"全网平均值"，分不清新华社通稿和自媒体洗稿。差异化 = 把信源治理做成基础设施。

### 竞品具体做法

- **智慧公文系统（党政采购市场，如无忧智慧公文）**：技术指标可直接借用为验收标准——审核覆盖 6 大类 46 小类错误，政治审核准确率 ≥99%、召回率 ≥95%；内置黑名单 100 万+、白名单 37 万+、敏感词、落马官员、重要人物 2 万+、固定搭配、重要讲话、法律条文 85 万+；支持用户自建词库、私有化部署、每月至少更新一次。
- **黑马校对**：基于万亿字语料与 800 万条错误规则库，可校对省部级以上领导人姓名、职务、排序错误，涉台及敏感政治性错误；特点是"及时同步新华社、中宣部的要求到规则库并发布更新"；全国 95% 以上出版社在用，已作为 WPS 365 内置能力，开放系统集成接口。
- **RAG 工程界**：置信度评分低于阈值触发人工审核或结构化拒答；引用溯源被视为"生产环境 RAG 的必需品，不是可选项"。

### 报告建议的分级体系

| 等级 | 典型来源 | 使用规则 |
|---|---|---|
| S / 一级权威 | 新华社通稿、人民日报、求是、学习强国首发、中国政府网、党章党规原文 | 可直接引用，作为理论、政策、人物职务、关键事实的主要依据 |
| A / 二级权威 | 省级党报、高校官网、权威学术期刊、教育部平台资源 | 可引用但标注来源，必要时交叉验证 |
| B / 用户贡献 | 教师投稿、转载材料、课堂记录 | 默认未验证；须审核员核验且至少一个 S/A 级信源佐证后才入生成语料 |
| C / 未核验 | 互联网抓取、自媒体 | 仅作线索，不进入生成语料 |
| AI 生成 | AI 摘要、AI 改写 | 永远不是原始事实来源，只是派生内容 |

置信度 ≠ 模型输出概率，而由**来源等级 + 来源数量 + 证据直接性 + 发布时间 + 新旧版本一致性 + 人工审核状态**共同决定。一个一级权威来源直接支持的陈述，比十篇转载文章更可靠。

每条素材强制携带元数据：原始链接、发布机构、栏目、作者、发布时间、采集时间、正文快照、版权状态、内容指纹、更新历史、来源等级、人工审核状态、可引用范围。

### 对本 demo 的启示

- demo 素材已有 `credibility/sourceUrl/level` 字段但靠手填（`app/data.js`），缺分级治理流程：谁来定级、何时审、证据是什么。
- 原网页更新/删除后，案例需要知道用的是哪个历史版本——正文快照与更新历史当前缺失。

## F3 检索

**要解决的问题**：教师五种找素材的场景（已知关键词 / 只记得只言片语 / 按主题语义找 / 从知识点反查 / 以优秀案例找同类），单一向量检索撑不住。

### 竞品具体做法

- **Anthropic Contextual Retrieval**：为每个分块加上下文后，组合语义检索 + BM25 + 重排序，显著降低检索失败率——单一向量检索不足以支撑严肃知识场景。
- **微软 GraphRAG**：普通相似度 RAG 擅长局部明确问题；GraphRAG 处理"全库共同主题""某思政元素在不同专业如何体现"等全局问题。报告建议 MVP 不做，素材量与全局查询需求增长后再建。
- **Dify**：功能最全的开源 LLM 应用平台，RAG 管道端到端透明可配（父子分块、混合检索、reranking），适合深度调优与多模型切换；可私有化部署。
- **FastGPT**：轻量开箱即用的知识库问答，部署简单、API 兼容 OpenAI，适合快速搭私有知识库。
- **RagFlow**：以深度文档理解（DeepDoc）见长——用视觉语言模型做版面分析，识别表格、图片、标题层级、脚注；可视化分块预览、可手动调整切片边界；**答案可精确定位到原文片段并高亮**，最贴合"可追溯性要求极高"的场景。80k+ GitHub star，持续活跃（v0.25.x，2026-05）。
- **Coze 扣子**：插件生态与多渠道发布强，但知识库偏黑盒、可配置性低。
- **超星 / 智慧树**：把课程目标、知识点、教学资源、考核、案例、思政元素关联成图谱，支持"从知识点反查资源与案例"。

### 报告建议的检索设计

- 五种检索方式：关键词（已知人物/政策/事件）、模糊（只记得部分表达）、语义（"找一个体现工程责任和风险意识的近期案例"）、图谱（从知识点/思政元素/教学目标反查）、相似案例（以优秀案例找同结构不同专业）。
- 三个检索区域：**已审核库 / 权威外部源 / 一般外部源**，默认只在已审核库检索，结果不足才外扩。
- 三个库视图：**私有库（我的素材案例）/ 机构库（本校共享）/ 公共库（平台众创）**，检索范围与生成语料范围按视图隔离——不同安全等级的内容绝不混库。
- 结果卡片字段：标题、来源、发布日期、素材类型、适用课程、思政元素、审核状态、引用次数、更新时间。
- 排序：权威性 × 相关性 × 新鲜度 × 教学可用性 × 审核状态，不只按语义相似度。
- 结构化筛选：思政主题 × 学科知识点 × 教学环节三维标签体系。

### 对本 demo 的启示

- 当前前端本地 BM25（`store.js:802`）与服务端 BM25（`server.py:649`）两套口径不一致，且服务端检索从前端 UI 不可达——量级上到万条后必须收敛为服务端混合检索。
- 检索命中应到**切片级**（ADR 0010 的结构路径深链已具备基础），而不是整文件。

## F4 知识图谱与知识点关联

### 竞品具体做法

- **超星**：知识图谱关联课程目标、知识点、教学资源、考核、案例和思政元素；AI 工作台含视频理解、文献阅读、AI 出题、AI 教案。
- **智慧树**：用知识图谱推动课程知识结构化、体系化和交叉融合，国内已有思政课图谱实践。
- **大思政课数字地图（易班 univs.cn）**：按地理与主题聚合实践教学基地资源，用标签化和知识图谱解决"专业知识点关联思政主题"——"自动关联知识和素材"的直接先例。
- **学术框架**：思政课知识图谱围绕知识内容、关联关系、映射关系三要素构建；映射关系实现"培养目标 → 能力要求 → 问题体系 → 知识体系"逐级转化；构建步骤 = 专家整理知识框架 → 开发标注教学资源（教材章节挂接图谱节点）→ 图谱与资源库动态优化。已知短板：思政元素仅作孤立节点外挂、跨学科资源数据孤岛、依赖人工录入缺教学实践数据优化。
- **西安邮电大学《离散数学》课程组**："知识—问题—思政"三维图谱与案例生成引擎联动，而非独立建图。

### 对本 demo 的启示

- demo 的图谱（`app/js/graph.js`）目前是展示品。报告共识是图谱 schema 现成、缺的是高质量思政元素实例与素材的持续喂养——**图谱应作为检索与推荐入口**（ADR 0004 已把图谱并入检索页，方向一致），并回答"为什么这个素材适合这门课"（知识点—案例矛盾—思政元素—教学动作—学习结果的教学关系图谱）。

## F5 案例生成与模板

### 竞品具体做法

- **MagicSchool AI**：60–80+ 个预置 prompt 的单任务工具（教案生成器、测验生成器、量规生成器、文本分层器），教师选工具、填年级/标准/主题等少量参数即得成品；官方称每周省 7–10 小时；覆盖 160+ 国家近 600 万教育者；免费 + Plus（$8.33/月）；把 FERPA/COPPA 合规与 93% Common Sense 隐私评级当核心卖点——**信任状前置展示**。
- **Diffit**：按主题、原文、年级生成分层阅读材料、活动、课堂站点、替课材料、幻灯片；可导出到 Google/Microsoft 工具；突出适龄化与分层。
- **Brisk Teaching**：浏览器扩展嵌入教师正在用的文档、网页、视频、LMS，抓当前页面作为生成上下文——不建新工作入口，覆盖教师原有工作流。
- **Curipod**：AI 生成教师控制的互动课堂（讨论、投票、写作活动、实时反馈）——案例不止是文章，要直接转成提问、讨论、投票、板书、退出测验等课堂动作。
- **讯飞星火教师助手**：对话式交互，一键生成符合新课标的单元教学规划、分层试卷、跨学科课件；预置官方赛事课件模板。
- **希沃**："1+N+N"体系（1 个教学大模型 + N 个教学场景 + N 个智能终端）；输入课件名称自动生成贴合新课标与核心素养的教学设计、大纲、课件；集成集体备课、听评课；**教师画像、个人课件风格、课堂反馈进入下一轮备课**——"上一课影响下一课"的闭环。
- **电子科大 i 思政大模型**：教案生成、在线命题、作业批改、课后辅导（智能助教）+ 5R+ 智慧思政中心（智能伴学）+ 学情测评（智能画像）；校内封闭系统。
- **浙大"AI 思政一点通"**：基础大模型 + RAG + 校内权威语料；立项动机明确为"弥补通用大模型内容生成来源可信度无法确定的不足"；覆盖 5000+ 本科生并输出到其他高校——验证了可信来源是思政场景选 RAG 的首要动机。
- **案例微观结构事实标准**：人民卫生出版社《中医护理学课程思政案例库》构建"思政主题、思政目标、案例内容、思政分析、使用方法及微课/说课的完整体系"；中国专业学位案例中心收录 5095 篇案例、服务 517 家单位，其评审标准可作案例模板与基准测试集来源。
- **思政元素挖掘方法论**（学术界）：四条融合路径——嵌套式、外延式、条件式、过程式；四个挖掘角度——从理论知识点挖辩证思想、从服务国家战略挖"四个自信"、从学科史与中国科学家贡献挖爱国情怀、从教学过程挖工匠精神。**这套方法论可直接转写为 AI 生成的 prompt 框架与质检清单。**

### 报告建议的生成结构

- "稳定骨架 + 可变教学策略"：骨架 = 课程信息、案例背景、知识目标、价值目标、原始材料、理论联系、教学过程、课堂问题、总结、引用；可变 = 导入方式、问题链、角色讨论、对比案例、数据分析、情境模拟、板书、测验、课后任务。
- 思政契合度拆成四个可解释维度：**知识相关性**（素材是否真涉及本课程的概念/机制/方法/职业场景）、**价值自然性**（思政元素是否从专业知识和案例矛盾中自然产生而非贴标签）、**教学可实施性**（能否通过提问/讨论/操作让学生形成理解）、**表述规范性**（理论、政策、职务、时间、术语与权威来源一致）。
- 不能在案例末尾简单追加价值口号，必须说明"专业知识点—现实矛盾—价值判断—教学活动—预期学习结果"的具体关系。
- 关键事实宁可提示"当前资料不足，无法生成"，也不要按常识补齐。

### 对本 demo 的启示

- demo 的模板 + kit（教学设计/讨论题/PPT 提纲）已接近"稳定骨架+可变策略"；缺的是**把思政元素挖掘路径内置进 prompt**，以及契合度四维量规作为生成后自检项。

## F6 编辑体验

### 竞品具体做法

- **Microsoft Copilot in Word**：在文档内起草、续写、改写、调整语气、总结；可引用现有文件作为生成依据；选中文本后局部修改；生成内容可替换、插入或继续编辑——教师几乎不离开文档。
- **WPS AI / 智能文档**：最接近中国教师熟悉的类 Word 体验；模板、排版、导出、多人协作成本低。
- **Notion**：块状编辑器 + 数据库 + 页面内 Agent（创建/修改页面和数据库）+ Enterprise Search；页面负责人、验证页面等机制适合内容治理。
- **飞书文档**：实时协作、评论、@提及、任务分配、精细权限；知识问答遵循企业权限继承。
- **OnlyOffice（技术路线 A）**：开源协作套件，OOXML 核心格式保证与 Word 高度兼容；快速/严谨两种协同模式、修订跟踪、评论、权限分级；可通过 document.key 机制接入自建应用——MVP 快速获得 Word 级体验。
- **Tiptap/ProseMirror 自研（技术路线 B）**：灵活但需自实现 docx 保真转换与协同算法（Yjs）；优势是可把"模板字段"做成结构化块、把"逐句引用"做成句级锚点，长期贴合"生成—审核—溯源"一体化。

### 共识与启示

- 老师不应先进入聊天页，而应进入案例编辑页；AI 作用于整个文档或选中段落；**生成内容以修订模式出现，由教师接受或拒绝**（可比较版本），而不是一次生成后覆盖原文。
- 三栏界面：左侧素材/知识点/思政元素/参考案例，中间可编辑正文，右侧生成、改写、引用核查、风险审查、审稿意见。
- 对本 demo：工作台（`pages-workbench.js`）的块编辑器 + 批注 + 版本快照已接近该形态；**缺"修订模式"**——AI 生成目前是插入/替换，不是可逐条接受/拒绝的 diff。

## F7 引用溯源与证据审计

### 竞品具体做法

- **NotebookLM / Gemini Notebook**：核心原则是 source-grounding——只根据用户上传的资料作答，回答逐句带行内引用编号，**点击引用直接跳回原文对应段落**；每个笔记本是一个隔离的素材空间（对应"案例间隔离"）；只答库内有的内容（防"子虚乌有"）。2026-07 更名为 Gemini Notebook，更名后保留的核心问题不变："我能不能沿着一段答案，走回一份自己愿意相信的证据？"与本平台差异：不做来源权威性分级。
- **RagFlow**：答案可精确定位到原文片段并高亮；可视化分块让用户看到检索命中的具体切片。
- **Wikipedia 可验证性原则**：有争议或可能被质疑的内容必须提供直接支持该陈述的行内引用——机制可直接迁移到案例生成。
- **RAG 工程共识（citation 三重保障）**：chunk 标识 + prompt 约束（仅基于检索材料作答、材料不足时结构化拒答）+ 后处理验证（引用是否真实支持句子）；置信度低于阈值触发人工审核或拒答。
- **RAGAS**：把检索相关性、答案忠实度、答案相关性拆开评价——"系统找到了材料"不等于"生成文本忠实使用了材料"。
- **NIST**：将生成式 AI"自信地输出错误或虚假内容"定义为重要风险，建议部署前和持续监测中核验来源与引用。

### 报告建议的机制

- **三类文本分层**：事实陈述（必须有证据，不允许自由发散）/ 理论解释（必须依据规范知识库，可解释但接受专业审稿）/ 教学设计（可创造性发散，但不得新增未经证实的事实）。
- 事实性句子**强制逐句引用**：引用与句子或段落绑定，不统一堆在文末；点击即可查看原文证据、来源、发布时间、采集版本，并显示信源等级——教师一眼看出每句话的"底气"。

### 对本 demo 的启示

- 当前 `citations[]` 是教师手工挂接的块级引用（ADR 0005 已定文末参考文献区 + 双向互跳），离"生成时被证据约束的句级锚点 + 证据面板"还差：句级锚点模型、证据片段存储、引用蕴含校验（审校员增加"引用是否支持该句"判断）。

## F8 内容安全：政治性差错与"低级红高级黑"

### 竞品具体做法

- **黑马校对**：该领域事实标准。万亿字语料 + 800 万条错误规则库；校对省部级以上领导人姓名、职务、排序错误，涉台及敏感政治性错误、落马官员；支持重点词/敏感词监控库自定义；速度 10 万–300 万字/小时；全国 95%+ 出版社在用；规则库及时同步新华社、中宣部要求；WPS 365 内置；开放系统集成校对接口。
- **蜜度"校对通"**：大模型时代形态。基于文修大模型，覆盖文字标点差错、知识性差错、内容导向风险、版面格式 **4 大类 46 小类**错敏问题，含姓名职务准确性、法律法规引用规范、**党内法规表述一致性**；支持文本、图片、音视频多模态批量校对；官方称准确率 98%+；2025 WAIC 发布校对智能体，一句指令即可完成文字校对、检索查证、交叉核稿、分析统计、勘误报告生成全流程；政务场景严格依据《党政机关公文处理工作条例》筛查时政重点表述错误。
- **智慧公文系统**：验收指标级能力（见 F2）：政治审核准确率 ≥99%、召回率 ≥95%。
- **政府侧"三审三校"（对照组）**：重庆市政府部门年报做法——"严格落实信息发布'三审三校'制度……全年未出现'低级红''高级黑'等意识形态错误"。说明这类风险的防控目前主要依靠制度而非算法。

### 报告建议的审核体系

- **"机审确定性问题 + 人审判断性问题"双层结构**：错别字、领导人姓名职务排序、涉台表述、引文与原文一致性、素材真伪——机器负责，须达公文级准确率；价值导向是否恰当、思政元素结合是否生硬（"贴标签""两张皮"）、是否过度拔高——交给教师本人 + 教研组互评 + 机构审核员。
- 六道审核层：来源审核（白名单/链接有效/转载）→ 事实审核（实体抽取、多源比对）→ 引用审核（逐句蕴含判断）→ 理论与术语审核（权威术语库、固定表述库比对）→ 思政契合审核（量规 + 反例库）→ 教学审核（学段/课时/可执行性）。
- **反例库**至少覆盖十类：虚构事实、引用伪造、职务错误、时间错置、概念混淆、牵强映射、过度拔高、负面案例失焦、表述不规范、版权与隐私。
- "低级红高级黑"不能简化为关键词过滤（夸张吹捧、绝对化、庸俗化、娱乐化、反讽），机器可发现风险信号，最终仍需懂政策、懂课程、懂学生的人工审核。
- 合规预留：《人工智能生成合成内容标识办法》（2025 实施）要求 AI 生成内容标识；数据模型应提前支持"AI 生成 / AI 辅助 / 人工作品、审核人、模型版本"标记。
- 记忆写入也要过政治性差错过滤，防止"记住一次错误表达并在后续复用"。

### 对本 demo 的启示

- 校对能力宜直接采购黑马/蜜度 API（`.env` 已有 `AI_REVIEW_ENABLED` 开关位），自研重心放在思政垂直词库（教材固定表述、二十大及历次全会表述、教材版本差异）的持续维护。
- demo 的 MoA 审校员（`server.py:808-856`）是通用 LLM 自查，需要接入权威词库比对 + 反例库才算"机审"。

## F9 审核流与协作治理

### 竞品具体做法

- **GitHub Pull Request**：贡献者提交修改，审核人逐行评论、批准或要求修改，所有变化和讨论保留历史——众筹式互评互改的治理范本。
- **MERLOT**：同行评审 + 成员评论评价教学资源。
- **OER Commons**：资源提交、协作、质量审查基础设施。
- **中国专业学位案例中心**：多轮专家评审 + 作者反复修改 + 入库情况纳入国家专业学位授权审核与评估考核指标；收录 5095 篇、517 家培养单位、500 万+ 浏览；与哈佛商学院出版社互换 26 个案例。**"投稿—评审—入库—反哺职称评估"的激励闭环**。
- **新华思政申报制**：教师申报 → 学校书面同意盖章 → 平台审核上线；申报即承诺无政治性、科学性错误。

### 报告建议的状态机与分级

- 素材/案例状态机：草稿 → 待机器检查 → 待同行审核 → 专业审核通过 → 校级认证 → 平台精选 → 过期或撤回。

### 对本 demo 的启示

## F10 记忆与个性化

### 竞品具体做法

- **Letta（前 MemGPT，UC Berkeley）**：把 LLM 当作运行在受限内存 OS 上的进程，设 Core/Recall/Archival 三级记忆，由 Agent 自主决定记什么、摘要什么、归档什么。
- **Mem0**：向量 + 知识图谱双存储；写入时自动抽取结构化事实并去重；按 session/user/agent/organization 作用域隔离；服务化 API 轻量接入。
- **Zep**：时序知识图谱为核心，每条边带有效性窗口，适合事实随时间变化的场景。
- **希沃教师画像**：教师风格、课件偏好、课堂反馈进入下一轮备课，形成"越用越懂你"。

### 报告建议的三层记忆

- **偏好记忆**：教师喜欢的篇幅、模板、语言难度、提问数量、课堂时长、活动风格（如"喜欢朴实课堂语言、案例 800 字、偏好本省案例"）。
- **组织记忆**：学校/教研组认可的模板、优秀案例、常用思政元素、审稿意见、被拒绝的表达。
- **事实记忆**：不存在聊天历史里，必须存在带来源和有效期的知识库中。
- 警示：行业记忆基准数据水分大（同一基准厂商自测与第三方评测可差 45 分），选型应自建小评测集验证。

### 风险警示：用户级记忆是 harness 的高危件（2026-08-05 补充）

用户级 memory 很容易"做着做着就崩了"，从提效件退化成拖累 agent 的 harness：

- **不可调试性**：记忆注入后，教师会问"它为什么突然这么写？"——自动记忆让生成行为变得不可解释，与产品"可审计"的核心卖点直接冲突。
- **记忆漂移与污染**：记住一次不当表述（甚至一次政治性错误表达）并在后续反复复用，风险被放大；通用记忆框架不会替你做政治过滤。
- **上下文膨胀与冲突**：每轮生成都要检索注入记忆，prompt 越来越长，且记忆结论可能与证据层冲突（"老师上次这么写过" vs "权威来源不是这样"）——证据层必须永远赢，这要求记忆层天生低人一等，而多数记忆框架不这么设计。
- **基准不可信**：行业记忆基准水分大（厂商自测与第三方评测可差 45 分），Mem0/Letta/Zep 的宣传数字不能作为选型依据。

结论：**先做 bench 再决定做不做自动记忆**。从用户视角建小评测集（见 TODO 文档 P2 节），对比"无记忆 / 显式偏好表单 / 自动记忆"三种方案；过渡期用显式偏好表单（教师自己填、可解释、可删），大概率这就是 MVP 的正解。

### 对本 demo 的启示

- 记忆的前提是反馈沉淀（F12 的飞轮）；demo 当前教师修改完即消失，无 diff 存档，无从谈记忆。即使有沉淀，也先做显式偏好，自动记忆必须过自研 bench 验证后才允许进 harness。

## F11 自动化与 Agent 平台

- **腾讯 WorkBuddy**："派任务—交付成品"心智（用户更易接受交付结果的任务型 Agent，而非与聊天机器人反复讨论）；Skill/专家/专家组三级抽象；多 Agent 并行；统一模型接入与切换；团队权限；本地与云端文件处理 + 对象存储保存文件与生成内容。
- **模型切换原则**：只影响写作风格、规划能力、生成速度、成本；**事实、引用、术语必须来自统一证据层**——模型之上要有独立的证据、规则和审计层。
- **多模型协作职责分工**：一个模型做素材抽取、一个做教学规划、一个负责表达、一个独立模型做事实和风险审查；所有模型都不能绕过证据层。

### 对本 demo 的启示

- demo 的 MoA 编排（主 Agent 路由 / 资料管理员 / 写作手 / 审校员，`server.py:1169`）已是该架构雏形；需要补的是审校员背后的权威证据层与规则库，而非更聪明的 prompt。

## F12 众筹机制与激励（数据飞轮）

### 竞品具体做法

- **成果认定驱动供稿（最强激励）**：专业学位案例中心入库 = 国家评估考核指标；新华思政上线 = 学校学科建设喜报（"6 门课程上线新华思政平台"）。思政案例供给侧激励天然绑定"教学成果"叙事——上线证书、使用量报告、年度优秀案例评选、向权威平台推荐输送，比现金稿酬更有效。
- **GitHub 式**：fork（改编他人案例生成自己版本并保留溯源链）、star、PR 提交改进——案例谱系可追溯恰好服务审计。
- **维基百科式**："每句话都要有来源"的可供查证方针 + 巡查制度，与"每句话都要有引用"同构，可作社区内容规范话语蓝本。
- **Stack Overflow 式**：声誉积分与徽章驱动贡献。
- **西南交通大学土木学院**：以平台为依托申报国家教学成果奖——机构侧看板服务教学评估与成果奖申报。

### 报告建议的机制

- 先审后发：预发布状态贡献仅自己/本机构可见，审核通过才进公共库——政府"三审三校"逻辑向平台机制的平移。
- 推荐排序：来源质量 + 专业审核 + 课堂使用次数 + 教师收藏 + 修改幅度 + 学生反馈 + 更新时间的组合；点赞只反映受欢迎程度，不能替代准确性。
- 贡献者信誉**按领域拆分**：机械工程课程思政的高质量贡献者不应自动获得审核医学、历史、理论政策内容的权限。
- 完整飞轮：教师选材和生成 → AI 提出草稿 → 引用与风险自动审查 → 专家修改 → 课堂实际使用 → 教师评价 → 修改内容沉淀为规则、模板和反例 → 下一次生成更准确。

### 对本 demo 的启示

- 远期项。前置条件是使用量统计（`citedCount` 已有，ADR 0003）与修改 diff 存档；之后才能有"被引用/被改编"数据反馈和领域信誉。
