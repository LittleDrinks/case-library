# 案例资料与课题组通用知识：产品边界研究

核验日期：2026-10-01。范围：已有案例资料区，加上供课题组学习的 PDF、教材、政策等通用知识；不重新选择存储技术，不引入私人通用资料库。本报告只读官方产品文档；下面的最小模型是工程与产品建议，尚待用户决定，不是行业强制标准。

## 结论

“文件管理共用一套能力”与“所有资料必须放同一个产品库”是两个决定。成熟产品会区分文件、具有来源/标题等含义的资料条目、以及资料在某个课程或内容中的使用关系；它们并没有规定案例资料与课题组学习资料必须统一成一个面向用户的库。[Moodle 文件复用](https://docs.moodle.org/502/en/Working_with_files#Creating_a_link_to_a_file)、[Drupal Media](https://www.drupal.org/docs/8/core/modules/media/overview)、[Zotero 条目与附件](https://www.zotero.org/support/adding_items_to_zotero#standalone_attachments_and_parent_items)

建议保留用户熟悉的“这篇案例的资料区”，另提供“课题组学习资料”入口；二者可以共用上传、文件读取、来源记录和权限检查。通用知识不必先挂到某篇案例；案例需要时，再明确选一条学习资料加入本案例，并记录它在这里的用途。不要因共用文件而自动把所有案例资料变成公共知识。

## 2. 用教师实际动作区分三个概念

老师上传《课程思政教学参考.pdf》时，**文件**回答“内容是哪一批字节”。**资料条目**回答“这是哪本教材、谁发布、哪一版、为什么值得读”。在《社区治理》案例里添加它时，**案例使用记录**回答“这个案例引用了哪一版、哪一章/页、用于说明什么”。这个分层是从上述官方产品行为推导的项目建议。

同一本教材可以供课题组平时学习，也可以被两篇案例引用；它不必被复制成两份独立教材条目。相反，两位老师上传字节相同的 PDF，也不能单靠内容相同就认定来源、权限和业务意义都相同。

一份针对《社区治理》案例的访谈附件，则可以仅属于这篇案例；没有需要时，不必自动出现在课题组学习资料入口。是否选为通用学习资料，是显式整理动作，不是上传的必然后果。

## 3. 归属、复用、权限与时效应分别判断

下表为本项目的推荐判断维度，官方来源支持它们可以分开建模，并不提供本平台的默认产品规则。

| 独立问题 | 例子 | 不能直接推出的另一项 |
| --- | --- | --- |
| 属于哪个业务上下文？ | 一篇案例的采访资料；课题组整理的教材。 | 属于课题组不等于任何匿名访问者都能下载。 |
| 谁负责维护？ | 教材条目由管理员维护；案例用途说明由案例作者填写。 | 有管理权不等于可以读取他人私人资料。 |
| 可在哪些地方复用？ | 课题组教材可被案例选用；案例附件暂不提供跨案例选择。 | 可以复用不等于已有案例会跟随新版自动改变。 |
| 谁能找到条目、读内容？ | 可公开看到政策条目，但某份教材文件只供获校内资格的人读取。 | 看见标题/摘要不等于有 PDF 的读取权限。 |
| 内容处于什么时效状态？ | 政策已被新版取代；旧版仍是某篇历史案例的依据。 | 过时不等于删除，更不等于旧案例应悄悄改用新版。 |

## 4. 保留案例资料区体验的最小模型

下面是待确认建议，不要求先建一个复杂的统一资料库：

1. **案例资料继续在案例内操作。** 作者在本篇案例上传资料、说明来源与用途；当前投稿/发布和下载权限边界继续适用。
2. **增加课题组学习资料入口。** 通用 PDF、教材、政策可独立登记，不要求创建“占位案例”；首版由管理员维护是一种降低整理成本的候选，不是本轮已确认规则。
3. **两类资料按需相连。** 在案例资料区提供“从学习资料中选择”，形成案例使用记录；移除本案例的使用记录，不删除课题组条目。把案例资料收录为学习资料也需要显式操作与来源/权限核对，不自动迁移全部既有资料。
4. **历史依据和当前学习版本分开。** 学习入口可展示当前推荐版本及“已被新版取代”；投稿/发布案例保留当时选择的具体版本。此推荐延续本项目冻结审核的需求，并得到 Moodle 提交禁止可变链接场景的类比支持。
5. **共享基础能力，保持明确业务权限。** 两个入口可以共用文件存储、上传处理、校内资格判断；展示/下载仍分别按授权检查。管理员身份不自动获得未投稿草稿、私人资料或 AI 对话读取权。

条目字段建议从“标题、资料类型、来源、版本/日期、简短用途说明、读取范围”起步；确实有政策时效管理需要再补“有效/被替代、替代条目”。这些是小型平台适用的字段候选，不是官方标准。没有条目元数据的文件也应允许先待整理，避免让用户为每个 PDF 填复杂书目表。

## 5. 三个简单验收场景

- **教材平时学习：** 管理员登记一本教材，课题组成员从学习资料入口找到并读取；这本教材没有挂到任何案例，也能完成学习。
- **案例复用政策：** 作者写《社区治理》案例，从学习资料中选择一份政策，补“本案例使用第 3 条”；读案例时仍在该案例资料区看见这一引用，不要求用户先转去一个统一库理解它。
- **政策更新：** 管理员加入新版，并标出旧版已被替代。新的案例可选新版；历史案例仍标示自己当时使用旧版。是否继续允许旧文件下载，与“它过时了”分开处理。

## 6. 后续采访的决策点

1. 学习资料首版只由管理员整理，还是允许普通用户提交资料、管理员审核后收录？不要把“普通用户可以写案例”直接推成“普通用户可以维护课题组知识”。
2. 教师从学习资料区主要需要“找资料阅读/下载”，还是首版就需要 AI 回答时自动检索这些资料？后者应明确检索范围和引用展示，不能仅因上传了 PDF 就承诺知识问答。
3. 课题组学习资料是否全部采用既有校内资格开放，还是其中部分公共资料也可匿名读取？这是读取范围选择，与资料是否属于某篇案例无关。

“是否统一一个界面/一个数据库集合”可以在这三类用户动作明确后再判断；共用文件基础能力已经足以避免重复建设，不需要先让用户选择抽象库架构。
