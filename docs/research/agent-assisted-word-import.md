# Agent 整理 Word
## 已核实事实
项目已依赖 `python-docx==1.2.0`，见 `backend/requirements.txt` 与 `backend/requirements.lock`。
| 来源 | 能力与边界 |
| --- | --- |
| `docx_document` | `Document` 读取 `.docx` 文件或字节流；`iter_inner_content()` 按文档顺序产生段落和表格。`paragraphs` 不包含修订标记内段落；`tables` 只列顶层表格，不包含嵌套表格或修订标记内表格，不能把两个列表当作全部内容。 |
| `docx_pictures` | Word 区分行内图片和浮动图形；官方高层图片支持以行内图片为界。只读段落文字不足以保留图片及其位置，也不能据此承诺所有浮动图形完整转换。 |
| `markitdown` | Microsoft 先把 Word 等文件转换成供 LLM 使用的 Markdown，保留标题、列表、表格、链接等结构；官方明确不以面向人的高保真转换为目标。图片 OCR、描述是附加处理能力，文本输出不能代替图片资源。 |
## 已确认方向
教师先创建草稿，再向该案例的 Agent 对话提交 Word，执行 extract；创建草稿不要求填完标签。只提取可以读取的内容，保留字句与原章节，转换为可编辑结构，不自动润色、补写缺失内容或套平台教学模板。
图片支持上传；从 Word 提取的图片进入资料区，正文关联同一资源并保留可还原的位置，表格提取为可编辑表格。无法还原的图表明确提示，不用模型描述替代原图。
处理中显示灰色条目与转圈，成功保存后恢复正常显示，失败显示叉号；保留成功部分，标明未提取内容，部分完成不表示整份文件完整还原。原文件供任务处理与重试临时使用，任务结束后清理，不长期保存或加入参考资料。
提取作用于当前草稿，正文采用延续待确认修改规则；成功提取本身不授权覆盖教师已有内容。
## 推论与建议
“由 Agent 处理”可以是单一用户动作，内部仍需要读取工具提供正文、结构和图片；模型无法用提示词恢复读取阶段没有取得的内容。现有依赖可先用于核验实际教师样本，尚未决定增加或更换库。
提示词约束不能单独证明保真。应核对提取文本与生成草稿的内容差异，并检查段落、表格、图片是否有遗漏；发现差异时给出具体位置，避免只用 Agent 自报成功。
图片应保存为可访问的图片资源，正文需要图片时关联该资源。OCR 文字或模型描述仅辅助理解，不能替换原图；成功状态应以资源保存和正文关联完成为依据。
## 验证
使用正文、嵌套表格、修订、行内图片、浮动图片和不完整草稿核验读取覆盖率、内容差异和资料状态。未安装新依赖，未调用模型，未执行转换或端到端验收。
