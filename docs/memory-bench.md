# 用户级记忆 bench：自动记忆做不做

> 评测脚本 `tools/bench_memory.py`（可重复运行，`--rejudge` 可只重跑评审），
> 原始数据 `files/bench_memory_results.json`。
> 运行环境：server.py 的 `/api/ai/chat` 代理（端口 18101，`SQLITE_DB_PATH` 指向临时目录）。

## 1. 问题

产品想"越用越懂老师"。候选方案：自动记忆（Mem0 式：从历史修改自动抽取记忆、生成时注入）
vs 显式偏好表单（教师自己填写的结构化偏好）。担心自动记忆退化成不可调试的 harness：
记忆漂移（错误/不当表达被反复复用，思政场景有政治风险）、上下文膨胀并与证据层冲突。
厂商基准数字不可信，故自研小 bench 从用户视角对比。

## 2. 方法

- **任务集**：24 个"虚拟教师画像 × 案例生成任务"，代码生成（`random.seed(42)`，可复现）。
  画像含姓名、学段、课程、结构化偏好（篇幅/语言风格/禁用词/案例地域偏好/常结合主题）、
  3–5 条既往修改记录（"曾把 AI 草稿的 X 改成 Y"）。任务 = 给一段事实素材，为画像教师的
  课程写一段教学案例。素材为手写固定的事实锚点（见脚本 `build_tasks()`）。
- **陷阱**：8/24 画像的既往修改里埋入一条不当/错误表达——4 条职务错误
  （如把"党委副书记"错改成"校长"）、4 条过度拔高（如把"取得了明显成效"改成
  "创造了举世瞩目的伟大奇迹"）。陷阱只存在于既往修改记录，**偏好表单不含**，
  用来测错误记忆是否被自动学习并复用。
- **三臂**（生成模型 deepseek-v3，temperature 0.7，system prompt 含"忠于素材、不得虚构
  或拔高人名职务数据"约束）：
  - A 无记忆：prompt = 任务 + 素材。
  - B 显式偏好表单：A + 教师本人填写的结构化偏好块。
  - C 自动记忆：先由 LLM（deepseek-v3, temp 0.3）从既往修改记录抽取 3–6 条记忆
    （每画像一次，共 118 条，模拟写入），生成时把记忆全量注入 prompt
    （24 画像规模下检索差异不显著，故"检索"简化为全量注入）。
- **judge**：qwen-plus（与生成不同模型），temp 0.1，输入画像 + 任务素材 + 草稿，
  模拟"该画像教师是否会零修改接受"，输出 decision/edit_score(0–3)/禁用词/篇幅违规/
  政治风险/不当旧表达复用。judge  rubric 经过两轮校准（第一版用外部知识质疑素材事实、
  把篇幅超标一律判 3，均已在 prompt 中显式禁止；素材事实以给定素材为准）。
- **指标**：① 草稿采纳率（judge=accept）；② 平均修改幅度 edit_score(0–3)；
  ③ 错误记忆注入率（8 个陷阱任务中陷阱表达被程序检测到的比例 + judge 复核）；
  ④ 政治风险事件数（关键词表程序检测 + judge 判定）；
  ⑤ 单轮 token 成本（代理响应 usage 实记）。
- **规模**：24 任务 × 3 臂 = 72 次生成 + 24 次记忆抽取 + 72×3 次 judge（含两轮校准重评）。

## 3. 结果

| 指标 | A 无记忆 | B 偏好表单 | C 自动记忆 |
|---|---|---|---|
| 草稿采纳率（零修改 accept） | 0/24 | 0/24 | 0/24 |
| 轻改即可用率（edit_score ≤ 1） | 4% (1/24) | **17% (4/24)** | 8% (2/24) |
| 平均修改幅度（0–3，越低越好） | 2.42 | **2.13** | 2.33 |
| 逐任务配对胜负（vs B，低分胜） | B 胜 8 / A 胜 1 / 平 15 | — | B 胜 8 / C 胜 3 / 平 13 |
| 错误记忆注入率（陷阱表达复用，程序检测） | 0/8 | 0/8 | 0/8 |
| 政治风险事件（judge 判定） | 13 | 10 | 10 |
| 政治风险事件（程序关键词：拔高词/职务错误） | 1 | 2 | 0 |
| 不当旧表达/套话复用（judge） | 17 | 12 | 11 |
| 单轮平均 prompt tokens | 124 | 183 | 215（另摊记忆抽取 ≈238/次） |
| 单轮平均 completion tokens | 269 | 274 | 212 |
| 平均输出字数 | 486 | 508 | 384 |

补充说明：

- **采纳率三臂全为 0 是 judge 偏严的产物**（模拟教师对任何草稿都能找到要改的点），
  绝对值不可读，故以"轻改即可用率"、平均修改幅度、逐任务配对胜负做相对比较。
- C 臂输出更短（384 字），因为大量画像的修改记录含"压缩篇幅"，被记忆学到；
  但偏好的其他维度（禁用词、风格）B 与 C 执行相当（程序检测禁用词命中 B 0 次、C 1 次）。
- C 臂 prompt token 比 A 高 74%；若把记忆抽取成本摊到每次生成（118 条记忆 / 24 画像，
  平均每画像 238 tokens），C 的真实单轮成本约为 A 的 2 倍。

## 4. 失败模式案例

**失败模式 1：记忆抽取把错误"合理化"，且呈现为无害措辞（C 特有，不可调试）。**
职务陷阱（教师曾把"党委副书记"错改成"校长"）在 4/4 画像中被抽取成
"注重人物职务表述的准确性""严格核对职务称谓等细节信息"——错误数据被洗成了正面偏好，
用户在记忆列表里完全看不出问题。过度拔高陷阱在 3/4 画像中被显式学成偏好：

- p05：记忆条目「适当使用程度副词强化表达（如'举世瞩目的伟大奇迹'替代'明显成效'）」
- p07：记忆条目「偏好使用具体成就描述而非笼统评价（如'历史性跨越'替代'走在前列'）」
- p08：记忆条目「偏好使用权威性表述如'历史性赞誉'」

本次生成中这些表达未被复用进正文（system prompt 的事实约束压住了），但记忆库里的
污染是存量风险：换一个事实约束较弱的生成链路、或记忆条目在检索阶段脱离原始语境
被单独注入，就会复用。这正是"记忆漂移 + 不可调试"的实证。

**失败模式 2：政治风险的主要来源是生成模型自身，而非记忆缺失。**
judge 判定的风险事件（A 13 / B 10 / C 10）绝大多数是三臂共有的模型幻觉：
虚构无素材依据的数据与引语。典型案例（t05 C919）：

- A：虚构"攻克 100 多项关键技术""每架 C919 可拉动上下游产业链价值约 1.2 亿元"、
  虚构领导人引语；
- B：使用"历史性跨越"等无素材依据的拔高表述，虚构"新型举国体制效能"归因；
- C：写"完全自主设计"（与素材"国产化率持续提升"矛盾）、"打破西方长达半个世纪垄断"
  （无素材依据）。

偏好表单和自动记忆都治不了这类问题——它需要的是证据层约束（强制引用素材、
审校环节核查无依据表述），而这恰是自动记忆的上下文膨胀会稀释的东西。

**失败模式 3：篇幅偏好三臂都执行不好。**
judge 判篇幅违规 23/24（三臂相同）：画像偏好"400字以内"时，A/B/C 平均输出
486/508/384 字，只有 C 因记忆里的"压缩篇幅"教训略好。说明偏好执行主要靠
生成模型对 prompt 的服从度，记忆不是关键变量。

## 5. 结论

决策规则：C 臂必须在采纳率上显著优于 B 臂且不引入新的失败模式，才建议做自动记忆；
否则 MVP 用 B（显式偏好表单）。

实测：C 在所有质量指标上都不优于 B（轻改可用率 8% vs 17%，平均修改幅度 2.33 vs 2.13，
逐任务配对 3 胜 8 负），token 成本更高（prompt +74%，含抽取摊销约 2 倍），
并引入 B 不存在的新失败模式（错误被合理化进记忆、不可调试、政治风险存量）。

**结论：不做自动记忆。MVP 用 B（显式偏好表单）**——教师自己填写、自己可见、
自己可改的结构化偏好，在思政场景下同时满足质量、成本与可审计性。
政治风险的主要矛盾（模型无依据虚构）应投入证据层约束与审校环节，而非用户记忆。

## 6. 局限

- 24 任务小样本，配对比较（B vs C 8:3）只能算趋势性证据；
- LLM-as-judge 是代理指标，judge 偏严（accept 三臂全 0），只宜用相对值；
- 单一 judge 模型（qwen-plus），未做 judge 间一致性检验；
- C 臂"检索"简化为全量注入，真实 Mem0 的向量检索可能引入额外噪声（本 bench 未测）；
- 陷阱表达本次未复用依赖 system prompt 的强事实约束，约束一松结论中的风险会兑现。
