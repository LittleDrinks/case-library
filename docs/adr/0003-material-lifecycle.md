# ADR 0003：素材生命周期策略（查重 / 使用度 / 淘汰）

状态：策略已定案；本轮仅落地「使用度数据 + 管理列」，查重与淘汰流程部分后置（2026-07-19 grilling 会议）

## 背景

由首页新闻流讨论引出：新闻线索若成为素材会带来重复与质量稀释。用户明确：采集为素材不能是普通用户的随意动作；素材入库后要观察使用，长期无人用的应淘汰；素材唯一性要靠「先检索相似、能复用就不新建」保证。

## 决策

### 1. 查重（双重闸，采集入口侧）

- URL 查重：同一 URL 不允许重复入库。
- 相似度查重：用户粘贴链接采集时，用现有检索（BM25 + 分词）找 top-3 相似素材，提示「已有相似素材，可直接引用 / 仍要采集」。
- 本轮实现：采集入口的两步提示；后台批量导入沿用同一函数。

### 2. 「用」的定义

- 素材被案例正文引用（进入引用清单）才算「被用」；浏览详情页不算。
- 素材记录 `citedCount`（被引次数）与 `lastCitedAt`（最近被引时间），引用增删时维护。

### 3. 淘汰

- 满 30 天未被引用的素材自动标记「待淘汰」（低活跃）。
- 管理后台素材管理表显示「被引次数 / 最近被引 / 待淘汰」列；管理员每月一键确认清理，可个别豁免。
- 不自动删除。

### 4. 新闻流与素材的关系

- 新闻流只读跳原文（ADR 0002）；新闻 → 线索池 → 去重入库 的自动化流程**本轮不做**，仅记录为后续方向。
- 「采集为素材」入口维持现状（工作台 Copilot 粘贴链接），但加查重闸；不向普通用户提供新闻一键采集。

## 后果

- 素材详情页展示使用度数据（被引次数 / 最近被引 / 待淘汰标）。
- 管理后台素材表新增使用度列与「待淘汰」筛选。
- 引用增删的每个代码路径都要维护 `citedCount/lastCitedAt`（集中在 Store 的 cite/uncite 函数）。

## 明确不做

- 不做自动删除。
- 不做新闻线索池与自动入库（后续 ADR 再议）。
- 浏览量、点赞不计入「用」。
