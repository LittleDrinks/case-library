# ADR 0016：AI 写工具走确认制修订
agent 在三类资料工具之外增加写工具：提议修订、挂候选批注、标批注解决。写工具不直接写入正文，产出均为待确认结果——确认制取代直接写入，因为 agent 在长文档上自主连续修改时，教师需要逐段否决权和可回退的后悔药。
待确认修订以单段为粒度，内联嵌在正文原位（删除/新增高亮），必须附修改理由。agent 积压三条未确认修订即阻塞，教师逐条接受或拒绝后恢复，「继续生成」可提前放行。一批修订开始前自动保存版本快照，教师可一键回滚整批。
作者批注是 agent 的任务来源：正文内连续快标逐条挂批注，线程内「让 AI 解决」或批注面板批量交办，agent 逐条产出修订并在处理后标解决。批注由此同时承载人工意见与机器任务，不另设任务实体。
自检是 AI 对话中的一个动作：锁定当前版本快照、执行检查提示词，结果以批注呈现，不再是独立面板。轻量审核和提交前多 Agent 审核的所有结果都是建议批注，按理论、证据、教学或表达标识，不阻塞教师提交；管理员在审核中作最终判断。
已发布案例在工作台只读，作者要继续编辑须先由管理员下线回工作版本。

> 2026 更新（#214，M1 初稿写入）：确认制仍是默认路径；在此之上补充两类正文写工具。其一，教师消息明确「直接写入」且范围清楚时，`write_document` 由服务端校验后直接执行——授权由服务端在 Run 创建时从教师当前消息判定并冻结（仅直接肯定指令；引用、疑问、否定、条件与说明性提及不授权），不来自工具参数或模型自报；写入保留前后文档与撤销入口，整篇覆盖仅限真空文档或未编辑模板，选区写入仅限锁定的教师选区并保留块结构。其二，空草稿/模板可经 `propose_document` 产出整篇初稿候选，确认后写入。作者权限、只读隔离、修订号冲突与防重语义不变；写入一律使用结构化文档，不把 Markdown 标记当正文。
