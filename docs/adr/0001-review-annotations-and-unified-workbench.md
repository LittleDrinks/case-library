# ADR 0001：审核批注体系与作者/审核员统一工作台

状态：已定案（2026-07-19 grilling 会议）

## 背景

审核员需要说明退回原因，并可通过正文批注指出修改位置；作者与审核员共享工作台，编辑权限和审核动作按角色区分。

## 决策

### 1. 批注锚定：选区锚定

审核员（及作者）在正文中选中一段文字 → 旁边浮出「+ 批注」→ 批注记录选区原文（quote）+ 所在小节（h2 界定的块区间）。点击批注可定位到原句。锚点漂移时沿用现有模糊重挂（quote 前缀渐进匹配）+ 原文快照兜底；找不到显示「原文已变动」。

### 2. 退回理由与批注

- 审核动作「退回修改 / 要求补充」必须填写原因，不要求先创建批注。
- 审核员可追加定位批注说明具体修改位置。
- 批注不分类（无必改/建议/疑问分级），自由文本。
- 作者重新提交不做硬门槛（不强制全部批注已解决）。

### 3. 批注生命周期：跨轮线程

- 批注带状态（pending/resolved 等）跨轮保留。
- 作者可对每条批注「标记解决」并可附一句回应。
- 审核员二审时看到上轮批注 + 作者处理状态，可在**同一条批注下追加回复**（确认解决 / 追问重开），形成简短对话线程，不另开新批注。

### 4. 统一界面：审核页 = 工作台只读模式

- 审核详情页直接复用工作台的文档渲染、批注面板、Copilot，区别仅：文档只读 + 右侧增加「审核动作」区（通过/退回/要求补充/隐藏）。
- Copilot 对审核员提供：AI 审校（产出**候选批注**列表，审核员勾选后挂到正文）、提问、资料核查。
- 一份代码两种角色，消灭两套页面。

### 5. 自检批注化

- AI 自检建议以批注呈现，不作为投稿硬门槛。投稿校验标题、正文非空，以及每个管理员指定的必填标签组至少选择一个标签，不强制固定章节。
- 头部完整度徽标只保留计数显示，点开即跳到批注面板。

### 6. 版本模型

- 保存 = 在当前工作版本中保存（自动保存）。
- 提交 = 冻结当前内容并生成新版本号（v1、v2…）。
- 审核员审的是**某个版本的快照**；提交后案例冻结不可编辑。
- 审核结论产生前作者可撤回，恢复工作版本编辑；已撤回的提交不再接受审核决定。
- 审核通过即发布被审快照，不需要另点发布；退回后作者继续修改，再提交生成新版本号。
- 已发布案例可另开工作稿，旧版继续公开；新稿通过审核后成为默认发布版，历史引用仍定位原已发布版本。
- 已确认保存到案例正文或资料区的教学成果随案例审核；私人聊天和未采用建议不提交。

### 7. 审核页补强

- 版本对比：重新提交后显示上一版 vs 本版文字级 diff（增删高亮）。
- 历史审核记录：前几轮意见、批注及处理状态可见。
- 待审队列：加搜索框 + 提交时间排序 + 按作者筛选；显示完整度自检计数。

## 后果

- 定位批注承载具体修改意见与追问，退回原因独立记录。
- 工作台组件需抽成可被「作者模式/审核模式」复用的形态。
- 数据模型：annotation 增加 `replies[]`（线程）、`versionId`（归属哪轮版本）、`source`（selfcheck/ai/admin）。
- 新闻流线索池、素材淘汰等与本体系无关，见 ADR 0003。

## 明确不做

- 批注不做严重度分类。
- 重新提交不设批注处理硬门槛。
