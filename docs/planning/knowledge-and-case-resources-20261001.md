# 案例资料与通用知识：讨论记录

日期：2026-10-01。状态：研究与讨论草图已完成，产品边界待用户确认。未修改业务代码，未确定迁移方案，未新增已接受的 ADR。

## 起点与已知事实

用户希望保留当前“资料跟着案例走”的创作体验。同时，平台还需要不依附某一篇案例的通用内容，包括课题组统一学习 PDF、教材和政策。用户尚未决定这些内容应叫“知识”还是统一叫“素材”，也无法仅凭文字判断管理面板。

当前源码固定于 `7afc5bb9e182b1c61827d6024670002a42937fc6`：

- 案例资料区已合并案例附件、全局素材的挂载和其他已发布案例的固定版本来源。
- 编号是引用展示顺序；正文引用保存来源身份，并在案例范围核验。`caseID + enum` 不是当前文件或资料条目的唯一键。
- 全局素材已有导入、审批、检索、下载、加入案例的代码与界面；知识已有教材目录、节正文、检索和 Agent 读取，新内容目前靠固定教材 seed，缺少通用入库管理。
- PDF 已可存储、下载；当前文件文字抽取器没有 PDF 正文读取分支。不能把“上传教材”说成“已可基于教材进行 AI 问答”。
- 仅核对源码与界面草图，未验证生产部署。

详见 [当前模型研究](../research/case-resources-current-model-20261001.md) 与 [产品边界研究](../research/case-resources-and-shared-knowledge-20261001.md)。

## 候选语言与关系，尚未确认

候选总称为“资料”。案例资料属于一篇案例的创作和引用上下文；通用知识是可独立查找、阅读、被多篇案例选用的学习内容。两类都可以有文件，文件格式不决定业务归属。

具体例子：

| 内容 | 候选归属 | 时间信息与适用性 |
| --- | --- | --- |
| 此次社区调研现场照片、访谈摘要 | 本案例资料 | 拍摄/调研日期，不需要假设自动过期 |
| 工程伦理教材、课题组学习 PDF | 通用知识 | 版本、出版/整理日期 |
| 政策文件 | 通用知识；案例按需引用具体版本 | 发布、生效、失效日期或被新版替代 |

案例选用知识后，在案例资料区保留该知识的使用记录，不要求把所有案例附件变成共享资料；移除某次使用与删掉知识本身是不同动作。以上为待确认产品建议，不是对现有全局素材或知识数据自动迁移的授权。

已接受的 [统一案例资料区、固定版本引用与 Word 来源清单](https://github.com/LittleDrinks/case-library/issues/158) 约束来源固定版本与下线留来源条目，不因本轮重新讨论名称而重复打开这些决定。全局素材的版本冻结实现仍有缺口，应作为实现核对事项。

## 决策树

- 已定：保留案例资料区的创作体验；需要案例之外的通用学习内容；管理员默认无私人内容读取权。
- 当前可问：两类内容的产品边界和名称；通用学习内容首版的使用目标。
- 等边界明确后再问：通用内容如何收录与维护、能否将案例附件显式收录、文档版本和时效状态如何展示、后台以什么视角管理。
- 等生命周期明确后再问：从案例移除、停止使用、回收、永久清理及保留期。无需用户决定对象 key、数据库集合或存储适配器。

本轮问题：

1. 保留“案例资料区”，案例外另设“知识”，知识可独立存在并被案例选用；还是希望所有资料都从统一素材库进入？建议前者，后台可提供统一盘点。
2. 对教材、政策等内容，首版满足检索、阅读、下载和引用即可，还是还必须让 AI 基于文档回答并说明出处？建议后者，但应将“可供 AI 阅读”做成明确可验证的状态。

## 管理面板草图

[打开草图](../prototypes/knowledge-and-case-resources-prototype.html)，底部箭头或键盘左右键切换，URL `?variant=A|B|C` 保留选择。

- A：知识 / 案例资料分别进入；列表与右侧详情保持上下文。
- B：统一清单，通过归属筛选；同一页显示使用关系。
- C：从案例进入，展示本案例专用附件和引用的知识；知识亦有独立入口。

这三种只是后台布局比较，不分别决定数据库设计。数据全部为虚构示例，动作不调用应用 API。私人内容仅示意汇总占用，未展示私人文件名/内容。政策“待核查”只是时效表达候选，没有确认自动过期规则。

浏览器检查：A/B/C 切换、B 刷新保留选择、搜索定位一条现场照片、C 中查看某案例的四项资料以及详情开关均可用，无页面脚本错误。尚未选定界面，未促成生产功能。

### Claude 视觉重做

用户对第一版视觉不满意，并明确要求用 Herdr 派 Claude 重做。Claude 在同一工作目录的 `resource-ui` 面板完成 HTML、CSS 和布局重做，保留 A/B/C 三种视图与示例数据。网站导航、工具栏、文件列表、状态和抽屉统一调整；时间与适用性继续展示，未据此确认自动到期规则。

协调者独立打开实际页面，修复了字符编码、旧代码残留与手机网格溢出。桌面 1440×960 检查了三种布局、刷新保留选择、搜索、状态筛选、案例资料和详情；手机 390×844 检查了三种视图均无整页横向溢出，表格保留局部滚动，详情可以展开。独立文件打开也可用，无页面脚本错误。未验证其他浏览器；仍为可讨论的视觉原型，不是获选设计或上线功能。

### 用户反馈与素材掌控台迁入

用户明确喜欢列表中折角纸张形状、红色 PDF 字样的文件图标，要求保留；详情要求由右侧抽屉改为约占屏幕 80% 的居中浮窗。用户提出借用已经存在的素材掌控台，再做整合原型，尚未选择案例/知识的完整产品模型。

现有 [素材掌控台](../../frontend/src/views/MaterialExplorerView.vue) 有工作视图、来源权威性与素材类型筛选、公开素材过滤、搜索、分页，以及从草稿进入后的勾选和“加入当前案例”。现有 [素材详情](../../frontend/src/views/MaterialDetailView.vue) 已采用主内容与素材信息两栏。新草图以这些已实现的用户动作和布局为依据，不将后台盘点与作者选材混成一种权限。

旧原型的详情已修改：桌面宽高各为视口 80%，居中显示；手机使用更大的可读空间；打开时锁定背景滚动，关闭后恢复。已移除重复说明并验证关闭按钮和 Escape。新的整合原型路径为 [素材掌控台原型](../prototypes/material-console-prototype.html)，默认 D 方案，其余方案保留为比较。Claude 完成示例字段、D 方案状态与掌控台样式后遇到 API 重试；协调者停止该轮，完成渲染、交互与大浮窗两栏布局。PDF 图标的原始样式逐字保留。

独立浏览器核查已完成：默认 D 展示素材掌控台，搜索和刷新恢复、权威性与类型筛选、公开过滤、空结果清除、分页、勾选教材并加入当前草稿均可用；加入后当前案例资料显示五项，其他案例的专属图片不可勾选为共享资料。桌面详情测得宽高各为视口 80%，左侧为明确标注的示例文件预览，右侧为出处、权限、版本、引用和时间；支持关闭按钮、遮罩、Escape、焦点约束与背景滚动锁。手机 390×844 下 A/B/C/D 均无整页横向溢出，详情为单列，无页面脚本错误。双击 HTML 也能打开。没有真实 PDF 原件或下载，示例不调用生产 API；不能据此声称生产功能已迁移。
